# Security Policy

## MD5 Usage Justification

This project uses MD5 hashing in several locations. While MD5 is considered cryptographically weak and should not be used for security-critical purposes like password hashing or digital signatures, our usage is **intentional and safe** for the following reasons:

### Use Cases

#### 1. Nintendo 3DS File Integrity Verification
MD5 is used to verify the integrity of known Nintendo 3DS system files against hardcoded reference hashes:

- **Dev Certificate Chain** (`certchain-dev.bin`)
  - Expected hash: `d5c3d811a7eb87340aa9f4ab1841b6c4`
  - Files: `dsconv/crypto/certchain_provider.py`, `dsconv/legacy.py`
  
- **Boot9 ROM Encryption Keys**
  - Retail key hash: `e35bf88330f4f1b2bb6fd5b870a679ca`
  - Dev key hash: `49aa32c775608af6298ddc0fc6d18a7e`
  - Files: `dsconv/crypto/key_provider.py`, `dsconv/legacy.py`

#### 2. Test File Validation
MD5 is used alongside SHA256 for comparing output files in validation scripts:

- Files: `scripts/validate_refactor.py`
- Purpose: Ensure refactored code produces identical output to legacy implementation

### Why MD5 is Safe Here

1. **No Security Reliance**: MD5 is not being used for authentication, encryption, or any security-critical function
2. **Known Input Space**: We're verifying specific, known files against hardcoded hashes
3. **No Collision Risk**: We're not concerned about collision attacks because we control both the input and expected hash
4. **Cannot Change Algorithm**: The reference hashes are from Nintendo's official files and cannot be regenerated with a different algorithm

### Why Not Switch to SHA256?

The hardcoded MD5 hashes are **reference values** from Nintendo's official 3DS system files. We cannot change these to SHA256 because:

1. The hashes are not generated by us - they're verification values for specific Nintendo files
2. Changing the algorithm would break compatibility with existing file validation
3. The security concerns with MD5 (collision attacks, pre-image attacks) don't apply to our use case

### CodeQL Suppressions

All MD5 usages have been annotated with CodeQL suppressions and explanatory comments:

```python
# codeql[py/weak-cryptographic-algorithm]
```

These suppressions indicate that the MD5 usage has been reviewed and is intentionally safe for the specific use case.

## Reporting Security Issues

If you discover a security vulnerability in this project, please report it by:

1. Opening a GitHub Security Advisory in this repository
2. Or emailing the maintainer directly (see commit history for contact)

Please do **not** report security vulnerabilities through public GitHub issues.
